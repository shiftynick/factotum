# Completion audit

The reference is a copy-and-adapt starter for Linux, GitHub and subscription-backed Codex/Claude. The source project was inspected read-only; its identity, private runtime and product assumptions are absent from this repository. The first implementation includes two independent fictional adoption stacks and a shared local console. Remote projects and project-specific production deployment remain declared extension points.

| Requirement | Implemented path and evidence |
| --- | --- |
| Durable authorized execution | Core transactions, pinned inputs, supervisor receipts and explicit uncertainty; recovery, authority, concurrency and process tests exercise actual SQLite and supervised processes. |
| Reviewed delivery | Installed source/plan/build/review/check/merge/closeout workflow; live JavaScript and Python deliveries used different builder/reviewer families, actual GitHub merges and owned cleanup. |
| Plan before build capacity | `flow.plan`, queue preplanning and a bounded active-plus-ready window; planning integration tests execute the supervised flow, validate cached worktrees and reject stale authority/context/target. |
| Continuous queue | Merge settlement invalidates main health and configured automation enqueues baseline verification; new work uses owned trees at the verified remote target while the operator checkout remains unchanged. Real bare-Git tests exercise target advancement and preservation. |
| Stop, revoke and recover | Canonical dispatch fences, owned cancellation, late receipt settlement and conditional resume; tests cover live-owner reconciliation and crash recovery. |
| Alternate outcomes | Exact-head existing-PR adoption and explicit already-satisfied review/check/acceptance; deterministic adoption tests and a live already-satisfied run retain distinct evidence. |
| One console, multiple projects | Versioned project sockets, identity handshake, separate command journals and project-qualified actions; service tests and real Chrome checks cover identity overlap, response loss and independent decisions. |
| Operational controls | Scoped schedules/jobs, main health, host-wide heavy-work leases, backup/restore, retention and immutable upgrades; tests exercise actual files, resources and preservation failures. |
| Feedback through runtime | Audit findings deduplicate into unapproved follow-ups; completed flows persist retrospectives; rule challenges remain proposals; question/resource waits and numeric machine observations feed measured metrics. Later regressions require attributed operator reports. Integration tests exercise admission and settlement rather than only helpers. |
| Project replacement points | Adoption, provider, GitHub, context and extension guides plus optional release/product-evaluation labs. Both copied stacks execute actual project acceptance commands. |
| Host independence | Canonical local inbox and CLI remain usable without the console or optional T3 host. T3 guidance is optional; the runtime imports no T3 SDK. |
| Spending boundary | Subscription CLI routes are qualified; conflicting metered credentials fail closed. Metered APIs and paid experiments remain disabled. |

The final counts, executor fingerprints, live scope and residual limits are recorded in [qualification](qualification.md) and its [machine-readable record](qualification.json). Deterministic provider fixtures establish orchestration and validation behavior; they do not establish model judgment or remote atomicity. The full delivery, controlled-defect correction and already-satisfied observations are separately identified as live qualification.

Automatic merge remains disabled pending a qualified remote target-race mechanism. Production release adapters, hostile-code isolation, remote transport and schema migrations are not claimed as completed features. A new project's actual tests, credentials, context, setup and operational ownership still require commissioning.
